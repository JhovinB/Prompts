18. CLASIFICACIÓN DE RIESGO Y SUITE OBLIGATORIA
==================================================

ADEMÁS DE GENERAR LA SUITE COMPLETA, CLASIFICA INTERNAMENTE CADA CASO SEGÚN SU IMPACTO Y RIESGO.

UTILIZA:

CRITICAL / P0
HIGH / P1
MEDIUM / P2
LOW / P3

CRITICAL / P0:
Casos cuya falla pueda provocar un impacto crítico en el sistema, negocio, seguridad o datos.

Considera CRITICAL cuando aplique:

- Pérdida de dinero.
- Doble débito.
- Doble crédito.
- Doble transferencia.
- Transferencia a una cuenta incorrecta.
- Alteración o corrupción de datos.
- Procesamiento duplicado.
- Pérdida de una transacción.
- Error de saldo.
- Error de estado financiero.
- Acceso no autorizado a información sensible.
- Acceso a información de otro cliente.
- Violación crítica de integridad referencial.
- Procesamiento de una operación inexistente.
- Procesamiento de una operación ya completada.
- Fallo de idempotencia en una operación financiera.
- Procesamiento incorrecto de eventos críticos.
- Pérdida de mensajes críticos.
- Duplicidad de eventos financieros.
- Procesamiento fuera de orden que genere impacto financiero.
- Fallos que permitan ejecutar una operación sin autorización.
- Fallos que puedan comprometer la integridad transaccional.

HIGH / P1:
Casos cuyo fallo tenga impacto funcional, de integración, seguridad, datos o negocio importante.

Considera HIGH cuando aplique:

- Validaciones críticas de campos.
- Identificadores inconsistentes.
- Cuenta inexistente.
- Producto incorrecto.
- Cliente incorrecto.
- Estado inválido.
- Catálogo incorrecto.
- Integración entre servicios incorrecta.
- Fallos de autenticación/autorización.
- Timeout de servicios dependientes.
- Retry incorrecto.
- Problemas de correlación/trazabilidad.
- Errores de procesamiento asíncrono.
- Mensajes no procesados.
- Errores de consumer/producer.
- Errores de persistencia.
- Respuestas HTTP incorrectas que afecten el flujo.
- Errores de contrato.
- Errores que impidan completar una operación de negocio.

MEDIUM / P2:
Casos importantes pero cuyo impacto sea controlable y no comprometa directamente una operación crítica.

Ejemplos:

- Validaciones de formato.
- Longitudes.
- Valores fuera de catálogo no críticos.
- Campos opcionales.
- Errores secundarios.
- Casos de compatibilidad.

LOW / P3:
Casos cuyo impacto sea bajo y que no afecten directamente la operación principal, integridad, seguridad o negocio.
